学习范围：**全员基础**。本页描述需要理解的科研流程与管理原则，供本组讨论完善；具体制度尚未确认，不设独立作业或额外提交要求。

## 课题推进的基本逻辑

| 环节 | 需要理解的问题 |
| --- | --- |
| 定义问题 | 研究对象、条件与目标是什么？为什么值得研究？ |
| 梳理已有工作 | 当前证据到哪里？不足来自数据、方法、机制认识还是应用约束？ |
| 提出假设 | 哪个判断可以由计算或观测支持、削弱或排除？ |
| 建立基线与对照 | 怎样判断改进有效？比较是否使用相同条件和评价标准？ |
| 分析结果 | 结果可信度怎样？是否存在数据、数值或模型问题？还有哪些解释？ |
| 作出阶段决策 | 继续、调整、补充验证还是结束当前路线？依据是什么？ |
| 形成结论 | 解决了什么问题，适用范围在哪里，留下什么可迁移认识？ |

研究会反复回到前面的环节。工作量、计算次数和模型复杂程度不直接等于科学进展；重要的是不确定性是否减少、判断是否有了依据。

## 研究记录与可追溯性

应理解为什么需要关联问题、代码版本、数据来源、软件环境、输入参数、随机因素、任务日志和结果位置。结论变化时，也需要保留变化的原因与证据。

指南仓库存放稳定知识与规范，课题仓库保存研究代码与说明，大型轨迹/权重/原始数据放在批准的存储中，仓库记录其位置、版本和获取方式。重要结果需要能追溯至具体输入，避免仅凭文件名或聊天记录恢复过程。

失败记录应区分环境错误、资源不足、程序实现问题、数值不稳定、模型不适用和假设未获支持。不同原因对应不同的下一步。

## 沟通与协作

沟通时围绕问题、证据、当前判断与需要的帮助组织信息。描述阻塞时给出背景、预期、实际现象与关键日志，避免只说“算不出来”。涉及目标、数据、方法或资源的重大变化，应及时同步相关研究人员。

Git 和 Issue 可用于追踪代码与问题，实际采用方式由课题组决定。共同修改文件或使用多个 Agent 时，需要明确各自范围，并理解合并、冲突、核验和回退。
