# LLM 与 Coding Agent

[返回首页](../README.md) · [Codex 阅读指南](Codex.md) · [DSH 阅读指南](DSH.md)

学习范围：**基本使用与科研核验为全员基础；Skills、MCP、插件和科研智能体开发为课题相关**。以 Codex 和 DeepSeek Harness（DSH）为例理解人与 Agent 协作。

## 需要补齐的知识

| 主题 | 核心内容 | 科研中的意义 |
| --- | --- | --- |
| LLM 基本认识 | 模型、上下文、token、输出不确定性、幻觉、知识时效性 | 判断哪些回答需要外部证据与独立检查 |
| Agent 与工具 | 模型、运行环境、文件、命令、工具调用、会话与权限 | 理解 Agent 怎样把语言任务变成实际操作 |
| 任务表达 | 问题背景、目标、输入输出、已有文件、物理约束、判断标准 | 减少对研究意图和数据含义的误解 |
| 上下文管理 | README、项目说明、持久指令、任务记录、关键文献与日志 | 保持跨会话工作的一致性，避免依赖聊天记忆 |
| 工作流程 | 阅读与理解、方案、实施、运行检查、结果解释、修改回退 | 让过程可检查，避免只接收最终答案 |
| 科研核验 | 公式、单位、参数、数据来源、模型假设、数值结果、引用 | 判断产物是否满足科学要求 |
| 进阶扩展 | Skills、MCP、插件、工具接口、工作流、评测 | 将稳定研究步骤组织成可复用流程 |

## 任务表达的基本要素

提出任务时说明：研究问题与用途；工作目录及可用资料；数据字段、单位与来源；期望输出；应遵守的物理和计算约束；可用环境与资源；如何检查结果。描述不完整时，应允许 Agent 先查阅文件并报告不确定点。

复杂任务宜分阶段检查。保留关键决策、参数来源、修改差异和运行日志；失败时先定位原因，避免反复更换提示词而不检查输入和环境。

## 科研核验的重点

- **代码层面**：文件来源、数组维度、单位转换、依赖环境、修改范围、运行日志。
- **模拟层面**：模型假设、边界条件、参数、收敛与采样、守恒和极限行为。
- **机器学习层面**：数据泄漏、分组划分、基线、评价对象、外推与不确定性。
- **文献与写作层面**：文献是否存在，来源是否支持主张，润色是否改变科学含义。

运行成功仅说明某段流程完成；科学结论需要相应的物理与研究证据。对关键结果，应回到原始数据、官方方法说明或独立的物理判断。

## 硕士与博士学习深度

| 硕士 | 博士 |
| --- | --- |
| 理解 Agent 的能力与局限；能够清楚描述任务、补充上下文、阅读差异与日志；核验影响结论的关键环节 | 在此基础上分析流程中的误差与失败模式；判断哪些步骤适合自动化；理解如何评估自动化的可靠性和可迁移性 |
| Skills、MCP 等先了解用途，随课题学习 | 与主课题相关时深入工具连接、工作流设计和评测；无需全员开发 Agent 框架 |
